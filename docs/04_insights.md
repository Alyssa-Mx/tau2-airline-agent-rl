# 04 · 思考：这个项目里真正学到的东西

这一篇不谈分数，谈判断。每一条后面写了它是从哪次失败里长出来的。

---

## 1. 两条线治的是同一个病，只是从两头下手

| | 奖励线（改训练信号） | 外壳线（改模型看到的输入） |
|---|---|---|
| 直接对着 | "做完没收尾 = 完全失败"这个信号缺陷 | "上下文过长 → 推理故障 → 对话被拖死"这个测量缺陷 |
| 机制 | 组内出现 1 / 0.5 / 0 的差异 → 有梯度 → 学会在预算内收尾 | 峰值 prompt 压到故障门槛以下，思考额度独立 → 判断有空间 |
| 压下去的（各自同引擎对照） | 截断率 17.5% → 11.2%，失败对话客服轮 18.4 → 16.4 | 截断率 18.8% → 6.2%，刷屏 25% → 0% |
| 没碰到的 | 写库题正确率（0.672 → 0.667） | 写库题正确率（0.722 → 0.694） |

**两条线的收益签名几乎一样**：涨的都是只读题和应拒绝题，写库题原地不动。而 DeepSeek 的优势恰好全在写库题上（0.833 vs 0.67–0.69）—— 我们两条线拿到的分，和强模型领先我们的那部分，不是同一种能力。

更底层的一句：**在所有 4B 配置上，通过的对话约 11 个客服轮，失败的 16–18 个；DeepSeek 通过 / 失败的对话长度几乎一样**。对 4B 来说，"失败"和"对话变长"在这份数据里几乎是同一件事；对强模型不是 —— 它失败时是一步走错，不是拖死。

## 2. 0/1 结果奖励的问题不在"稀疏"，在"混淆"

通常说结果奖励"稀疏"，意思是信号少。这里更具体：**0 这个值同时编码了三件毫不相干的事** —— 做对了没收尾、做错了、还没开始就跑飞了。GRPO 的优势是组内相对量，一组全 0 时这三件事的梯度都是 0；只要组里有一条成功，这三件事又拿到同样的负优势。模型从来没见过"收尾"和"做对"被分开的样本，自然学不到"在有限步数内收尾"。

所以部分分的设计原则是**先按"怎么结束的 + 题型"分类，再决定给不给分**，而不是再造一个连续的过程分。之前试过的过程分（写库 gold 召回）离线 AUC 很漂亮，上线后发现它的正优势 43–63% 发给了被截断 / 跑飞的对话 —— **离线 AUC 只证明"相关"，不证明"推的方向对"**。能用 0 卡的离线重判证伪的事，不要用 4 卡去证实。

## 3. DAPO 的超长过滤和部分分：同一个诊断，相反的处方

两者都认为"截断记 0"是坏信号，但 DAPO 把截断样本 mask 掉（减噪声），部分分给它 0.5（造信号）。实验结果把这个区别量了出来：成功率打平，**但只有给 0.5 的那组学会了收尾**（训练截断数 30 → 11，mask 组没有趋势）。理由很直白：mask = 对这类对话既不罚也不奖，模型没有任何理由去改变它。

附带学到：**mask 会加重梯度饥饿**（删样本后更多组变成全同），这就是 DAPO 要把超长过滤和 Dynamic Sampling 绑在一起用的原因。照搬一篇论文里的单个技巧之前，要先看它依赖的其他部件。

## 4. 测量装置的故障会伪装成模型能力问题

这一条是整个项目里最值钱的。四次"模型不行"最后都是测量问题：

| 看起来像 | 其实是 |
|---|---|
| 4B 长对话就崩、满屏 `!!!!` | vLLM 分块预填在 GDN 层上的数值故障；同权重 HF 在更长的 prompt 上 0/12 |
| 开思考没用 | 思考和回复共用一个 2,048 上限 |
| 思考模式下模型不回话 | 解析器在没有 `</think>` 时把整段当思考 |
| 训练后写库崩了 | 评测开了前缀缓存，刷屏后停不下来 |

判据只有一句：**先问"这个失败在更短的上下文 / 换一个推理后端 / 换一个解析器下还存在吗"**。能排除掉的都不是能力问题。

## 5. 单独有效 ≠ 能叠加

把部分分奖励第 6 轮的权重放进定版外壳（精简 + 思考）里评，反而比原模型**显著更差**（0.725 vs 0.825，−0.100\*）；在同一套外壳下，这份权重相对原模型只有 ±0.013，**思考的 +0.075 在它身上消失了**。

[推断] 在不开思考、原始 prompt 的 rollout 上训了 6 轮，权重绑定了训练时的外壳；外壳线的收益默认假设权重是原模型。要合起来，必须让训练 rollout 和评测用同一个外壳 —— 训练时就开思考、就用精简上下文。这是下一步最该做的事。

## 6. 统计上的几个习惯

- **永远报逐题配对差 + 区间**，不拿两个绝对分相减。20 道题上单组区间宽 ±0.13，配对之后才有分辨力。
- **比较规则事先写下来**。6 个 checkpoint × 2 组 = 12 个数，第 1、2 轮就出现过方向相反的"显著"；事后挑轮次总能挑出想要的结论。
- **每个兜底都要单独报触发次数，并核查它有没有引入新问题**。续写兜底触发 164 次 → 去查"它会不会编造写操作结果"（84 条里 1 条，是复述已有预订）；重采兜底触发 578 次 → 发现它兜不住、有选择偏差、换方案。
- **准确率没涨但把原因搞清楚的实验是成功的**。"单独精简不涨分"这个负结果直接决定了要开思考；"过程分无效"直接决定了部分分要先按结束方式分类。

## 7. 剩下的差距在哪里

和 DeepSeek 自演双方比，4B + 定版外壳在 pass@1 上已经分不出高低，但：
1. **截断率** 9% vs 1%（全部 50 题，显著）；
2. **每轮产出密度**：每个客服轮 0.5 个工具调用 vs 0.73–0.96 —— 4B 说话多、干活少，所以对话更长；
3. **写库题的判断**（选航班、算价格、付款方式）：两条线都没动，DeepSeek 在这里领先 0.14–0.17。几道写库题两条线都没有改善 —— t20 / t21 / t35 原模型 8/20、0/20、5/20，定版 2/4、0/4、1/4 —— 而 DeepSeek 自演是 3/4、2/4、4/4。

这三点指向同一个方向：下一步该教的是"每轮多干活、少说话"和写库前的核对，而不是继续调奖励的形状。
