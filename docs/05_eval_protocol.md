# 05 · 评测口径与统计方法

> 在这个规模上（30 道训练题 × 6 轮），**"测量条件"的效应量和"训练算法"的效应量是同一个数量级**：同一份权重换推理 TP（4 → 1）差 +0.0925（显著）。所以每个结论都先把测量条件钉死、再单变量比，并且只在同一套引擎内部比绝对分。

## 1. 任务与划分

- **τ²-bench airline**：50 道题，14 个工具（8 读 6 写），真实读写的航空公司数据库，`policy.md` 约 1,700 token。
- **划分**：`task_id % 5 ∈ {0, 1}` 的 20 道为 **held-out 测试题**，其余 30 道为训练题。训练线（所有 RL checkpoint）只报测试题；不训练的外壳线 50 道都没见过，额外报全部 50 题。
- 测试题的题型构成：写库 9 道、只读 6 道、无 gold 动作（应拒绝）5 道。无 gold 题最容易，所以测试集绝对分系统性高于训练题 —— **不能读成"泛化比拟合好"**。
- **用户模拟器**：DeepSeek-v4-Flash，temperature 0，经 OpenAI 兼容接口调用（训练和评测相同）。
- **每题 4 遍**，最多 40 步（每条消息算一步），seed 900，并发 32。

## 2. 指标

| 指标 | 定义 |
|---|---|
| **pass@1** | 全部对话的通过率（主指标） |
| **pass@4** | 4 遍里至少通过 1 次的题占比（能力上限）；遍数多于 4 时用无偏估计 1 − C(n−c,4)/C(n,4) |
| **pass^4** | 4 遍全部通过的题占比（稳定性，τ-bench 官方口径）；遍数多于 4 时用 C(c,4)/C(n,4) |
| **截断率** | `termination_reason == max_steps`（撞 40 步）的对话占比 |
| 宽松 / 严格 | 宽松 = 正常结束 且 DB × COMMUNICATE == 1（τ²-bench airline 官方 `reward_basis`，**主口径**，与训练奖励一致）；严格 = 再乘 ACTION（gold 动作全部按参数调用过） |

宽松分都是从 tau2 原始仿真结果离线重算的：结束原因不是 `user_stop` / `agent_stop` → 0，否则取 DB × COMMUNICATE。ACTION 只在对话结束后判分、不影响对话过程，所以同一批仿真可以两种口径都算。

## 3. 统计：逐题配对 bootstrap

- 两组比较一律 **逐题配对**：先对每道题算两组的差（例如两组各自 4 遍的通过率之差），再对 20 道题有放回重采样 10,000 次（`random.Random(0)`），取 2.5% / 97.5% 分位作 95% 区间。**\* = 区间不含 0**。
- 为什么不直接比两个绝对分：20 道题上单组 pass@1 的 95% 区间宽 ±0.13–0.15，几乎所有组都互相重叠；配对把"题目难度"这一项消掉之后才有分辨力。
- **噪声下界**：20 题 × 4 遍的配对区间半宽 ±0.06–0.13 → 单点差 ≤ 0.05 不作数。
- 实现：[`analysis/stats.py`](../analysis/stats.py)（只用标准库）。

## 4. 两套推理引擎（绝对分只在同一套内部比）

两条线用的是两套不同的调用方式，**跨引擎只比失败结构和题型分布，不比绝对分**。

| | 旧口径（奖励线各 checkpoint 的评测） | 原生口径（推理外壳线） |
|---|---|---|
| vLLM | 0.19.1，TP=1，前缀缓存关 | 同左 |
| 工具解析器 | `qwen3_xml` | `qwen3_coder`（Qwen3.5 官方推荐） |
| 思考 | 关 | 可开；思考解析器 `qwen3_toolend`（回移 vLLM PR #35687） |
| 每轮上限 | 2,048 | 不思考 2,048；思考 = 思考额度 4,096 + 回复 2,048 |
| 采样 | temperature 0.5 | 官方推荐：思考 temp 1.0 / top_p 0.95，不思考 temp 0.7 / top_p 0.8；top_k 20、presence_penalty 1.5；重复检测（1–20 token 片段连续 32 次即停） |
| 停止串 / 并行调用 | `</tool_call>`，一轮只能发一个工具调用 | 不设停止串，允许并行调用 |
| 客服实现 | tau2 原版 `llm_agent` | `lean_agent`（精简开关全关时与原版调用逻辑相同） |
| 原模型基线（测试集） | 0.738（20 遍 400 条） | 0.750（4 遍 80 条） |

启动方式见 [`harness/serve_vllm.sh`](../harness/serve_vllm.sh)（`ENGINE=legacy|native`）和 [`harness/run_eval.sh`](../harness/run_eval.sh)（`MODE=legacy|orig_nothink|lean_nothink|lean_think`）。

## 5. 踩过的测量坑（每一个都曾经让结论翻向）

| 伪装成 | 其实是 | 现在的做法 |
|---|---|---|
| "4B 能力不行，长对话就崩" | vLLM 0.19.1 分块预填在 Qwen3.5 GDN 层上的数值故障（[03 §4](03_context_harness.md#4-刷屏的根因推理引擎而不是模型)） | 盯 prompt 长度分布而不是刷屏计数；峰值控制在 1.2 万以下 |
| "开思考没用" | 思考和回复共用每轮 2,048，思考被截断 | 思考额度与回复上限分开 |
| "思考模式下模型不回话" | 解析器在没有 `</think>` 时把整段当思考 | 回移上游修复 + 补 `</think>` 续写；兜底次数单独报 |
| 某个 checkpoint 分数偏高 | tau2 遇到异常会整段重开对话，失败的那次不计分 → 选择偏差 | 报"重开次数 / infrastructure error 次数"，定版两者都是 0 |
| 训练后的权重"写库崩了" | 评测时开了前缀缓存：Qwen3.5 GDN 在 vLLM 0.19.1 上开缓存后，一旦刷屏 97–99% 的后续回复继续刷屏 | 评测一律关前缀缓存 |
| 同一组对照换个服务实例，结论从 +0.020 翻成 −0.0975 | 换了实例（原因没完全拆清）；另外同权重推理 TP 4 → 1 整体偏移 +0.0925 | 实验组和对照组在同一台服务、同一套采样上跑；TP、并发、缓存开关写进每次评测的 config |
| 某次对照"显著变差" | 复制评测脚本时漏了用户模拟器配置，用户由被测模型自己扮演 | 起评测后一分钟内核对 config 里的用户模型 |

## 6. 参照线：DeepSeek-v4-Flash

tau2 原版 `llm_agent`、客服 temp 0.5、每轮 2,048、不允许并行工具调用、40 步、seed 0，**客服和顾客都是 DeepSeek-v4-Flash**，50 题 × 4 遍（只走 API，不占 GPU）。测试集 0.875 / 全部 50 题 0.775。

这条参照线**偏高**：同一个模型同时扮演客服和顾客，它对自己的顾客更容易"对上暗号"。
